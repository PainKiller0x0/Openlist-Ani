# OpenList-Ani Rust 轻量化开发书

版本：1.0；编写日期：2026-10-12；对象：接手实现的 AI 开发代理。

## 交付性质

本包是完整开发规格、源码参考和自动化验收设计，不是已经实现的 Rust 软件。
`fixtures` 是测试输入与断言规格，不是通过测试的证明。不得把“规格检查通过”说成“产品测试通过”。

用户已同意：替换当前追番业务的 Python 后台；舍弃未启用的上游聊天助手、TUI、机器人前端和通知系统。
本次授权仅编写开发书；接手代理取得本包不等于取得立即改动生产环境、删除数据或推送 Git 的授权。

## 阅读顺序

1. `DEVELOPMENT_SPEC.md`：范围、实现框架、关键算法、数据与兼容规则。
2. `API_CONTRACT.md` + `reference/api-inventory.json`：保留的接口、校验和响应。
3. `TEST_PLAN.md` + `fixtures/acceptance-cases.json`：必须落实的自动化用例与判定。
4. `DEPLOYMENT_RUNBOOK.md`：只读预检、隔离测试、切换、回滚和线上验收。
5. `reference/README.md`：线上源码快照的使用方法与可信边界。
6. `IMPLEMENTATION_TASKS.md`：主代理与子代理可直接采用的工作拆分和完成判据。

本包附180条验收用例、14条命名golden、35个现有HTTP接口、26个Pydantic模型索引和246个源码/资产文件的hash快照。
开发前执行`python tools/verify-spec-package.py`可检查交接包完整性；这不是运行Rust产品测试。

## 不允许降低的交付标准

- 不得交付只有 HTTP 路由、没有真实 RSS/下载/重命名流程的空壳。
- 不得保留常驻 Python helper，也不得用 Rust 外壳启动原 Python 服务冒充轻量化。
- 不得将 LLM 解析换成纯正则以省事；生产当前使用 `llm` + `tmdb`。
- 不得删掉磁力/种子入口、蜜柑搜索、失败任务重试、详细命名设置。
- 不得重新把文件标题当作 TMDB 身份、目录名或订阅显示名。
- 不得同时启用两套实际下载扫描器；影子模式必须禁止外部写操作。
- 不得把模型/API 网络失败当作成功，也不得自动改标题反复绕过下载平台拒绝。
- 不得让用户承担常规回归测试；代理负责测试、截图、日志、报告和回滚演练。
- 不得把 fixture/mock 的通过结果冒充真实 HTTP、SQLite、进程恢复或 NAS/网盘验收。
- 不得部署未通过 Linux release 构建、数据库兼容测试和真实浏览器测试的版本。

## 推荐交付目录

用户仓库：<https://github.com/PainKiller0x0/Openlist-Ani>。
先检查仓库分支、未提交修改和线上差异，再在仓库新增 `rust/`；不要直接覆盖 Python 参考实现。
开发分支可命名 `rust-lightweight`。是否合并 main / push 必须取得用户明确授权。

## 给接手 AI 的执行指令

先提交一份可读的 `implementation-status.md`，列出所有接口和用例的实际实现/测试状态。
完成顺序为：兼容合同与样本 -> 本地数据库/纯算法 -> 外部接口适配 -> 持久下载状态机 -> 原 UI 实际浏览器验收 -> 性能与故障测试 -> 隔离预发布 -> 经授权部署。
这些是实现顺序，不是允许分期砍功能；最终交付必须满足完整范围。
遇到未知配置、未识别检查点或无法验证的真实外部服务时，明确列出阻塞项，不能通过填默认值、跳过测试或伪造成功来继续上线。
